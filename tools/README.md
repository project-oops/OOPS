# tools

Checks that span the repositories, and the tools that build the collection's sites. A check one
project can run on itself belongs in that project's gate; these need every project checked out,
or look at something a project cannot see about itself. Run them from the OOPS root;
`./bin/oops gates` runs the first four. Each script's header gives its usage.

## Gates

| Script | Checks |
|---|---|
| `check-decisions.sh [project]` | every decision log against [STYLE, decisions](../docs/STYLE.md#decisions): numeric order, no duplicate numbers, a date and a title on every entry |
| `check-links.sh [project]` | every relative markdown link and `#anchor` in tracked files, across repositories |
| `check-workflows.sh [project]` | every workflow that builds checks out OOPS, checks the project out into it, and runs `oops bootstrap` ([BUILDING.md](../docs/BUILDING.md#in-ci)) |
| `check-dashes.sh [project]` | no em-dash or en-dash in prose ([STYLE section 1](../docs/STYLE.md#1-write-what-is)) |
| `check-toolchain.sh` | every C repository pins the same clang major |

`decisions-baseline.txt` lists known decision-log failures, one `<project> <Dnnn> <kind>` key
per line. It only shrinks: a listed key that no longer fires fails the gate, and
`--prune-baseline` removes such keys. `--show-known` prints the listed failures.

`dashes-allowed.txt` lists the exact lines that keep a dash, such as captured output or text
quoted from elsewhere. Fenced blocks are not exempt.

## Generated indexes

| Script | Generates |
|---|---|
| `split-decisions.sh [--index] <project>` | `docs/decisions/Dnnn-*.md` from a single decision log, and `docs/DECISIONS.md` as their index |
| `split-doc.sh [--index] <project> <DOC> <level> <subdir>` | one file per heading of `docs/<DOC>.md`, and the document as their index; obSCEne's `docs/WORKLOG.md` is generated by it |

## Sites

| Script | Does |
|---|---|
| `build-docs.sh <project-dir> <out-dir> <accent> <title>` | renders a project's `docs/` to HTML; every `pages.yml` calls it |
| `build-apps-index.sh <apps-dir> <out-dir> <accent>` | builds the oops-apps catalogue page from each app's `app.env`, README and media |
| `publish-profile.sh [--check]` | assembles github.com/project-oops from the `oops:profile` sections of [README.md](../README.md) and publishes it, as `legboots`; `--check` fails when the published page differs |

`publish-profile.sh` runs by hand after the marked sections change: publishing writes to the
organisation's `.github` repository, which a workflow token cannot.

## Setup

`setup-wsl.sh` (`./bin/oops setup`) makes a machine able to build the C repositories; see
[BUILDING.md](../docs/BUILDING.md#windows-wsl-and-why-obscene-is-different).
`OOPS_WSL_NAME`, `OOPS_WSL_IMAGE` and `OOPS_WSL_LOCATION` change the distribution's name,
image and disk location.
