# tools

Checks that span all five repositories. Anything one project can check belongs in that
project's own gate; what lands here is what only the meta-repository can see - either because
it needs every project checked out at once, or because it is about something a project cannot
observe about itself.

Run from the OOPS root. **Everything here is shell**, like the `bin/*` entry points it sits
beside.

All four checkers were Python once, and that was a mistake nobody had decided on: the
collection is Rust, C and bash - 411 Rust files, 103 C, 50 shell, and **no Python at all in
any of the five projects**, which obSCEne's `CLAUDE.md` states outright. Four files in this
one directory turned out to be a far worse guide to the house language than the five hundred
beside them, and they were the guide followed anyway. Each was rewritten against its Python
original and checked to produce byte-identical output before the original was deleted.

## `check-decisions.sh`

Holds every `docs/DECISIONS.md` to [conventions §4](../docs/CONVENTIONS.md#4-decision-logs):
entries in numeric order, no number used twice, no gaps in the run, every entry titled, every
entry dated, and dates that do not run backwards.

```bash
tools/check-decisions.sh
```

Name a project to check just that one - `tools/check-decisions.sh selfish`.

**It found defects the first time it ran**, which is why it exists. A guard that has only ever
passed has not been shown to work; this one was written against defects that were already
there, and reported several hundred. What it reports today is only what is *new*, because the
several hundred moved into a baseline.

### The baseline, and why the gate is allowed to go green

Most of what it found cannot be fixed. Undated entries are undated because none of these
repositories had commit history when they were written, so the date is unrecoverable rather
than missing; the duplicates and out-of-order entries in orbistoun and obSCEne came from two
sessions writing one log at once, and
[conventions §4](../docs/CONVENTIONS.md#when-two-sessions-write-the-same-log) says the remedy
there is not for one side to choose alone.

So the gate could never pass, and a gate whose verdict is "fails" on every run it will ever
have says as much as one that has never fired - §8 makes that argument about a workflow on the
wrong branch, and this is the same defect from the other side. Worse, it buried the failures
that *are* actionable under three hundred that are not.

`decisions-baseline.txt` holds the known set, one key per line and no line numbers, so a key
survives the file being edited around it. It is a list rather than a count: §5's objection is
to numbers copied out of the thing that owns them, and this is regenerated by the tool.

**It can only shrink.** A key that no longer fires is itself a failure - a baseline nobody
prunes becomes a licence rather than a record. Fix an entry, drop its line:

```bash
tools/check-decisions.sh --update-baseline
```

`--show-known` enumerates the baselined failures alongside the new ones.

## `check-links.sh`

Resolves every relative markdown link and every `#anchor` in all five repositories.

```bash
tools/check-links.sh
```

Cross-repository links are the reason this lives here rather than in each project: from
orbistoun, `../selfish/docs/DECISIONS.md` exists or does not depending on what else is checked
out, and only this repository knows.

It **passes** today, and it earned that - it was written while the tree had six broken links and
it found all six. They were in `orbistoun/site/`, a Pages bundle CI regenerates, so the checker
now asks `git check-ignore` what to skip. Build output being wrong is not a documentation
defect, and a checker that reports it anyway is a checker somebody turns off.

## `check-workflows.sh`

Every workflow that touches a project's source uses the standard preamble: check out the
collection, check the project out **into** it, `oops bootstrap`.

```bash
tools/check-workflows.sh
tools/check-workflows.sh selfish
```

This is here rather than in each project for the inverse of the reason the other two are. They
need every repository at once; this one needs the thing a repository cannot see about itself.
A workflow checks *itself* out, and whether the collection is around it when it does looks
identical from inside either way - right up until the build fails as a missing directory.

**It found six defects the first time it ran**, in four repositories, and none of them would
ever have been reported: not one of these workflows has executed, because there are no remotes
yet. A flat checkout in orbistoun's `ci.yml`, `pages.yml` and release build, and in three of
obSCEne's jobs; a `defaults.run.working-directory` that made `OOPS/bin/oops` resolve to
`OOPS/<project>/OOPS/bin/oops`; and, in SELFish, no bootstrap step at all - on the strength of
a comment saying the project depended on nothing outside itself, which had been true when it
was written.

It has also been made to fail on purpose since, per
[conventions §8](../docs/CONVENTIONS.md): the bootstrap step was deleted from a job and it
named that job.

## `check-dashes.sh`

No em-dash or en-dash in prose. See
[conventions section 8](../docs/CONVENTIONS.md#dashes-are-hyphens).

```bash
tools/check-dashes.sh
tools/check-dashes.sh selfish
```

Here rather than in each project because the convention is one collection-wide rule, and five
copies of it is five things to drift.

**It was written after the conversion, not before it.** Two marks were in use for the same
job and the split ran roughly along repository lines without anybody deciding it - SELFish
leaned em-dash, the other four leaned hyphen, and every one of them used both in the hundreds.
3,231 were converted in a single pass while nothing had been published, which is the only
moment that is cheap; this exists so the next one does not arrive quietly.

The exemptions live in `tools/dashes-allowed.txt`, exact lines rather than a pattern, because a pattern
forgives the next one too. There are four: the decision-log parser's own strip set, the
convention that has to quote it, and two lines lifted verbatim from another project's source.

A fenced block is **not** exempt as a class. A captured session is evidence and keeps its
dashes; a hand-written comment inside an illustrative block is prose. Nothing can tell those
apart by looking at the fence, so a new one has to be added here deliberately.

It has been made to fail, per [conventions section 8](../docs/CONVENTIONS.md): a dash was
added to a document and it named the file and line.

## `publish-profile.sh`

Assembles the organisation's landing page at github.com/project-oops from the sections of
[README.md](../README.md) marked `oops:profile`, and publishes it.

```bash
tools/publish-profile.sh            # publish
tools/publish-profile.sh --check    # fail if what is published has drifted
```

GitHub renders an organisation profile from `profile/README.md` in a repository the
organisation must call **`.github`** - the name is GitHub's and cannot be changed, which is
why the landing page is not simply a file in this repository. So the second-best thing: it is
not *written* twice. The marked sections are the source, this assembles them, and every
repository-relative link is rewritten absolute on the way out, because a relative link
resolves against `.github` once published and 404s.

The same shape as obSCEne's `<!-- obscene:counts -->` blocks, for the same reason §5 gives.

**It is not in CI, deliberately.** `.github` is public, so a workflow could read it and
detect drift - but publishing needs write access to a repository in another namespace, which
the workflow's token does not have. CI could therefore report the problem and never fix it,
and the person able to fix it is the one running this locally in the first place. Run it
after changing the marked sections.

Publishing commits as `legboots`, pinned in the script rather than taken from whoever is
logged in. A local clone of `.github` would sit outside the OOPS root, where the `includeIf`
that binds that identity does not apply, and the first commit would carry the wrong author.
