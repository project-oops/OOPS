# AGENTS.md

Instructions for coding agents working anywhere in the OOPS collection.

Read, in order:

1. This file.
2. [docs/CONVENTIONS.md](docs/CONVENTIONS.md): provenance, naming, honest failure, gates,
   logging, tooling, toolchain, working across repositories.
3. [docs/STYLE.md](docs/STYLE.md): how code, comments, documents and commit messages are
   written.
4. The `AGENTS.md` or `CLAUDE.md` of the repository you are working in.

Repository files add to these and never restate them.

## 1. Look before you add

Before writing a new entry point, configuration option, storage path, helper or logging
facility, read [`oops-sdk/docs/API_INDEX.md`](oops-sdk/docs/API_INDEX.md) (generated by
`oops-sdk/tools/api-index.sh`) and grep the collection. The index shows what exists by
concept; grep shows how it is used. If it exists, use it.

When you do add something, the commit message says what you checked and why nothing fitted.

## 2. Keep the collection small

- Write code, not documents. [STYLE section 4](docs/STYLE.md#4-documents) lists every
  document a repository holds; anything else goes in a commit message, a line in `ISSUES.md`
  or a code comment.
- Write what is. No history, no storytelling, no status in code comments or documents.
- Record a decision only when it is a choice between real alternatives that constrains later
  work. Write a worklog entry only at a milestone.
- Leave the tree formatted and the gate green: `./bin/<project> check`.

## 3. Hardware safety

- Rendering code handles submit errors and fence timeouts by failing safe to CPU
  rasterization, logging, and never hanging the hardware ring.
- Verify with the repository's gate (`make test` in oops-sdk, `./bin/<project> check`
  elsewhere) before reporting work as done.

## 4. Models

| Model | Role |
|---|---|
| Gemini 3.8 Flash | primary driver of the loop: HLE translation, reading `pros logs` telemetry, test harnesses, mechanical diffs |
| Claude Opus 5 | compiler transformations (RDNA2 control flow, SPIR-V lowering), architecture, deep diagnosis |
| Fable 5.1 | symbol-candidate cross-checks and second hypotheses when the loop is ambiguous |

Anthropic models can halt on low-level security vocabulary. Frame work in clean-room
systems-engineering terms: "hardware abstraction", "conformance probing", "memory mapping",
"virtual memory layout", "dynamic linker relocation", "freestanding libc stubs".
